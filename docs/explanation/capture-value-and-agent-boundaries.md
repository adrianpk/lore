# Capture Value and Agent Boundaries

The value of Lore is avoided reinference. A useful entry preserves something
that is costly, non-obvious, recurring, or dangerous to rediscover: a recovery
sequence, a repository constraint, a known failure mode, or the correct route
to specialized documentation.

That does not imply exhaustive memory. Routine commands, transient status,
progress updates, copied documentation, and low-cost conclusions create noise
and make retrieval less reliable. Rarely used knowledge may still be valuable
when reconstructing it is expensive.

Capture and retrieval have different risk. Retrieval is bounded and read-only;
an agent can use it when relevant to current work. Capture creates durable
state and requires judgment about content, scope, and privacy. Lore therefore
starts with explicit capture: the human asks to preserve something and the
agent curates the reusable result without another approval round.

Autonomous capture may be enabled later by policy, but it should remain silent
and selective. Requiring approval for every proposed entry would interrupt
steering, while recording every plausible observation would fill the store
with noise. Periodic objective review and reversible lifecycle changes provide
the safer feedback loop.

Pruning follows the same boundary. Review can suggest candidates without
mutating data. Archive and invalidate preserve history. Physical deletion is a
distinct administrative action with an exact dry-run selection and explicit
confirmation token.
